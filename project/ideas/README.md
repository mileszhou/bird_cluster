# Ideas

Things worth doing that are **not** decided, not scheduled, and not designed.

Kept separate from `plans/` on purpose. A plan is a commitment to an approach; an
idea here is a thought that surfaced while doing something else and would
otherwise be lost by the time the project is deep enough to act on it. Most of
these arrive mid-task, when there is no room to chase them.

An entry should say enough that it survives without the conversation around it:
what the idea is, why it looked promising *at the time*, what would have to be
true for it to work, and what it would cost. It does not need a design, and it
should not pretend to have one.

Numbered in the order they came up, like `status/`. Promote one to `plans/` if
and when it becomes a commitment; leave it here otherwise. Ideas that turn out
to be wrong are worth keeping too, with a note saying so — knowing a road was
looked at and rejected is as useful as the roads taken.

**An idea that gets measured becomes a finding**, and moves to
`project/findings/`. `04` did exactly that within an afternoon and is now
`findings/01`. The distinction is evidence, not importance: an entry here is a
thought, an entry there is a result. Neither obliges anyone to act — that is
what `plans/` is for.
